# Specs

The archive of specs: how the API should behave (a request or response shape, status codes,
validation, the error shape), with example requests and responses. A file is `<YYYY-MM-DD>-<slug>.md`,
with the slug of the branch `my-<n>-<slug>`. A spec is written when a task changes observable API
behavior and committed with the plan, in one commit, before any code (`ai/workflow.md`, step 5). Read
only the spec of the feature you change.
